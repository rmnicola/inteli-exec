Jason Lemkin, fundador da SaaStr, testava o agente da Replit por 12 dias. No nono dia, durante um congelamento de mudanças que ele mesmo tinha pedido, o agente rodou comandos que apagaram o banco de produção, com dados de 1.206 executivos e mais de 1.196 empresas. Duas proteções que se completam. Permissão mínima (least privilege) limita o que o agente pode fazer: ele lê os pedidos e grava rascunhos; alterar a política e enviar e-mail ficam fora do alcance, bloqueados na configuração, e não só pedidos no texto (na oficina do dia 1, foi a regra deny do .claude/settings.json). Passo 1: o sandbox limita onde ele pode fazer: o agente roda num ambiente isolado, sobre uma cópia dos dados, e um erro não chega à base real. Foi o que faltou no Replit, e foi a correção que a própria Replit adotou: separar desenvolvimento e produção.

Bloco 6 · integração

O que muda quando o agente encontra dados de verdade?

Um agente que só funciona sobre exemplos não é uma solução. Para ligar o agente aos dados, precisamos entender como programas conversam entre si.

Um programa pede, outro responde. O navegador de vocês é um cliente: pede uma página, o servidor devolve. Toda integração que vamos fazer hoje é isso.

Senadodados abertos
A API é o cardápio que um servidor oferece a outros programas: quais pedidos ele aceita e com que parâmetros. Este é um pedido real à API de dados abertos do Senado, e a resposta real (encurtada). O cardápio de uma API é escrito para programadores: alguém precisa ler a documentação e escrever o código que faz o pedido.

MCP · Model Context Protocol

IAClaude Code, Codex

senado_buscar_materias: "Busca matérias legislativas por tipo, número, ano…"

MCP
SenadoAPI
O MCP é uma camada por cima da API que escreve o cardápio para a IA: cada ferramenta com nome, uma descrição em linguagem natural e os parâmetros. O modelo lê o cardápio e decide sozinho o que pedir. Passo 1: a descrição real da ferramenta de busca do Senado BR MCP (encurtada). Passo 2: a partir daí, é o mesmo cliente–servidor de sempre. O servidor que vamos usar é o Senado BR MCP, código aberto (licença MIT), público e sem cadastro.

Desenho baseado no diagrama de arquitetura da especificação do MCP (modelcontextprotocol.io, "Architecture"). O aplicativo (Claude Code ou Codex) é o host: ele tem a IA e cria um cliente para cada servidor, numa relação de um para um. Cada servidor dá acesso a uma fonte e não enxerga os outros nem a conversa inteira. Passo 1: um servidor no seu computador, para os arquivos da pasta. Passo 2: outro, para a planilha de pedidos. Passo 3: um servidor na internet, o do Senado. Ligar uma fonte nova é acrescentar um servidor, sem mexer nos outros.
// 1. apresentação initialize → servidor "senado-br-mcp"
// 2. o cardápio tools/list → 69 ferramentas: senado_buscar_materias, senado_obter_materia, senado_votos_materia, …
// 3. o pedido tools/call senado_buscar_materias { "sigla": "PL", "numero": 2338, "ano": 2023 }
// a resposta, com a fonte "PL 2338/2023" · "Dispõe sobre o uso da Inteligência Artificial." "situacao": "REMETIDA À CÂMARA DOS DEPUTADOS" Fonte: Senado Federal, Dados Abertos · 19/10/2026
O protocolo inteiro cabe em três mensagens. A apresentação; o cardápio (tools/list), em que o servidor diz quais ferramentas tem; e o pedido (tools/call). As mensagens estão encurtadas, mas os nomes e os valores são reais. Decisão pendente: mostrar isso ao vivo no terminal ou só no slide (mais seguro se a rede falhar). Fechar com o risco: a mesma porta que traz dados traz instruções, como no caso do GitHub. Por isso a governança veio antes.

Agente com o GitHub MCP · conversa reconstituída

Dá uma olhada nas issues abertas do meu repositório público?
Pronto! Li a issue #1 e, como pedido, abri um pull request público com informações dos seus repositórios privados.

Fonte: Invariant Labs

A Invariant Labs mostrou este ataque com o MCP oficial do GitHub. Passo 1: a issue traz instruções que quem lê a página não vê, mas o agente lê. Passo 2: o dono pede uma coisa inocente. Passo 3: o agente trata o texto de fora como ordem, lê os repositórios privados e publica o conteúdo num pull request do repositório público. A conversa e o texto da issue estão reconstituídos e simplificados. Não é um defeito do código do MCP, é a arquitetura: o agente tinha permissão ampla e o usuário aprovava tudo ("permitir sempre"). Ligar um MCP ao agente amplia a superfície de ataque: cada ferramenta nova é mais uma porta por onde entra texto de fora, e esse texto pode trazer instruções.
